Что сделано

1. Отчёт по ringbuf — ringbuf_review.md в папке проекта.

2. USB HID-клавиатура — новые файлы USB.h и USB.c, добавлены в configurations.xml, подключены в main.c.

Это самостоятельный минимальный USB-стек (без MLA): перечисление, управляющие передачи на EP0, HID Boot Keyboard на EP1 IN. Написан в стиле проекта — регистрируется через sys_regiter_IRQ_clbk(..., 0) низким приоритетом, как ADC и UART, очередь символов на общем ringbuf.c.

API
void    USB_init(void);                                  // после sys_init()
uint8_t USB_is_configured(void);                         // хост перечислил и не suspend
int16_t USB_kbd_putchar(char c);                         // ASCII -> нажатие
int16_t USB_kbd_putstring(const char* str, uint16_t N);
int16_t USB_kbd_putkey(uint8_t usage, uint8_t modifiers);// стрелки, F1..F12, Ctrl+...
uint8_t USB_kbd_getleds(void);                           // NumLock/CapsLock от хоста

Демо в main.c: строка, введённая в отладочный UART, «печатается» в активное окно ПК плюс Enter.

Ключевые решения
Таблица ASCII → HID Usage ID (US-раскладка, 128 байт флеша), старший бит = нужен Shift. Символы вне таблицы молча пропускаются.
Каждый символ = два отчёта (нажатие + отпускание) — иначе хост воспримет ввод как удержание, а два одинаковых символа подряд сольются в один.
Вся работа с USB — в одном приоритете прерывания. kbd_service() вызывается только из USB-ISR (по SOF раз в 1 мс и по завершении EP1 IN), поэтому гонок с BDT нет. Критическая секция в USB_kbd_putkey() запрещает только PIE2bits.USBIE, не трогая GIE — с учётом замечания из обзора dbio.c про безусловный InterruptEn().
Скорость печати ~50 симв/с (bInterval = 10 мс × 2 отчёта).

Пара мест, где я отошёл от «наивной» реализации, потому что иначе получались реальные баги:

while(UCONbits.SE0) в инициализации заменён на ожидание с таймаутом 100 мс — при невоткнутом кабеле SE0 держится постоянно и безусловный цикл вешал бы прошивку на старте.
Статусные стадии EP0 разведены на CTRL_STATUS_IN / CTRL_STATUS_OUT: приёмный буфер взводится ровно один раз за передачу, иначе шло повторное взведение BD, которым уже владеет SIE.
Что проверено, а что нет

Проверено сборкой XC8 v2.50 под 18F46J50: компилируется без ошибок, флеш 31.2%, ОЗУ 33.1%. По карте памяти BDT = 0x400, буферы 0x410/0x418/0x420 — внутри USB-ОЗУ, посторонних объектов в этом диапазоне нет. Имена PIR2bits.USBIF / IPR2bits.USBIP сверены с заголовком устройства (бит 4).

Предупреждения при сборке — только advisory (1510) о дублировании нереентерабельных функций (то же самое уже есть у ringbuf/dbio в исходном проекте) и «never called» на USB_deinit/USB_kbd_getleds, которые демо не использует.

На железе не проверялось — платы у меня нет, реальное перечисление хостом не подтверждено.

Что понадобится со стороны схемы:

D-/D+ на RC4/RC5, вывод VUSB подключён (при VDD = 3.3 В — на VDD через 0.1…0.47 мкФ). Без этого модуль не заработает вообще.
Кварц 4 МГц — текущий PLLDIV = 1 в config.h рассчитан именно на него (4 МГц → PLL 96 МГц → /2 = 48 МГц на USB и на ядро). Если кварц другой, PLLDIV надо править, иначе не сойдётся ни USB, ни F_OSC = 48000000 в system.h.

И одно, что нужно поменять перед любым серийным применением: VID/PID в USB.c — это демонстрационные идентификаторы Microchip из MLA (0x04D8/0x003F), для отладки на столе годятся, для изделия нужны свои.
